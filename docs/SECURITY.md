# Security — current local milestone

Phases 1–2 are a local development application. Do not publish it or expose its backend through a tunnel. Dependency advisories and inherited shared-module browser warnings remain open (see PHASE_0_RUNTIME.md and PHASE_1.md).

CEO controls require a generated 256-bit token, checked server-side for every write. `OFFICE_OWNER_TOKEN` is a backend environment variable; its local copy is `.office/owner-token.txt`. `.office/` and `.env.local` are ignored by Git. The browser stores the supplied token in memory only. The token is a bearer credential: anyone with the value can act as local owner; never share it, put it in a URL, film it or commit it. Public read-only local observation is permitted. Authenticated hosted identity/session management, HTTPS and authorisation review are prerequisites for deployment.

Legacy anonymous join/leave, generic engine inputs, message writes, and stop/resume cannot mutate the office. New financial/research functions must not be reachable through those legacy routes. Internal Convex functions and the local dashboard/CLI are trusted deployment administration: a person with machine or deployment-admin access can change backend secrets and data. The local token does not protect against a compromised development machine.

`OFFICE_PHASE=1` or `2` rejects model configuration before external inference requests. Phase 2 adds fixed-host, read-only public Kraken and credentialed Twelve Data price/candle adapters, server-side quotas and TEST-only deterministic paper execution. It includes no real brokerage/exchange order route, model runtime or web-research tool. Fixture data is segregated from provider data and cannot qualify an actual feed. Rights/session/corporate-action verification gates remain required before provider-source fills. Provider timestamps are never shifted to conceal clock errors. The proposed model label is not verified availability; billable model calls and paid data tiers still require their applicable owner checkpoint.

Local keys can be kept in **`.secrets.env`** in the checkout root. Git ignores this file and its backup suffixes; `.secrets.env.example` is the blank, tracked template. This is a plaintext local file, not encryption: Git ignore prevents accidental tracking, not access by someone who can read your machine or backups. Never use a `VITE_` prefix, paste a key in chat, or film the file.

After editing, run `node scripts/import-secrets.mjs`. It verifies the secret file is ignored/untracked and targets only the existing anonymous localhost Convex deployment, then pipes approved values into the backend environment without printing them or putting values in process arguments. `--check` validates configuration without importing or calling services. Phase 2 imports only `TWELVE_DATA_API_KEY`; future keys such as OPENAI_API_KEY can be stored locally but are not imported or enabled. Re-run after changing an approved key. `.env.local` stays separate and retains Convex-generated deployment URLs.

Alternatively, `scripts/set-market-key.ps1` still supports its hidden local prompt. Provider errors do not log credential-bearing URLs. Data-provider credentials do not authorise brokerage execution. Both local storage and the backend environment must be updated when rotating a key.

If the local token leaks, replace it securely in the local file and Convex environment, then lock/reload the browser. If environment selection is wrong, stop the local tools and inspect variable names/hosts without sharing secret values. Do not run wiping utilities to recover the office. Preserve the original world and audit history.
